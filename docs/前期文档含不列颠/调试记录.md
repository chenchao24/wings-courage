## 一、场景渲染调试

### 1.1 断崖黑白块锯齿（2026-08-04 ~ 08-05，多轮迭代）

**现象**：不列颠关卡海岸断崖立面白一块黑一块，色块明显，锯齿感强烈，海岸线斜度大处白色↔草地交界尤其明显。

**根因（两层）**：
1. **顶点着色受网格分辨率限制**：地形 segments=600，顶点间距 80m；断崖宽度 cliffWidth=80m，断崖区域只有 0-1 个顶点采样到，顶点颜色突变形成色块
2. **基于 z 的过渡带在斜度大处失效**：等高线接近 x 方向时，过渡带在垂直等高线方向投影 = `blur * cos(α)` 趋近 0，过渡带"消失"

**尝试方案**：

| 轮次 | 方案 | 结果 |
|---|---|---|
| 1 | 注释说"移至 onBeforeCompile 片元着色器" | ❌ 实际代码未注入，材质还是普通 MeshStandardMaterial，悬崖走顶点着色 |
| 2 | if/else 硬切换片元判定（按 vWorldPos.z 判区域） | ⚠️ 颜色精确但边界零过渡，锯齿感更强烈 |
| 3 | smoothstep 权重混合（blur=24m） | ✅ 黑白块消失，但斜度大处仍锯齿 |
| 4 | 各向异性 blur（blur=38*normFactor） | ✅ 彻底解决 |

**最终修复**：
- [terrain.js onBeforeCompile](file:///c:/Users/CC/Desktop/gameSpace727/darkWil/js/terrain.js)：注入片元着色器，按 `vWorldPos.xz` 像素级判定海滩/断崖/崖顶，smoothstep 权重混合
- 海岸线斜率归一化：`slope = cos(x*0.0006)*0.72 + cos(x*0.0017+2.1)*0.85 + cos(x*0.0041+4.3)*0.82`；`normFactor = sqrt(1+slope²)`；`blur = 38 * normFactor`
- 垂直等高线方向恒定 38m 过渡，斜度大时 z 方向自动放大到 ~98m

**关键教训**：
- 顶点着色无法解决窄特征（80m 宽断崖在 80m 顶点间距网格上），必须片元级判定
- 基于坐标轴的过渡带在斜向边界会失效，需用等高线法线方向归一化
- `onBeforeCompile` 注入后必须验证 uniform 真的被设置（第一轮就是注释说做了实际没做）

### 1.2 海洋塑料质感（2026-08-04）

**现象**：海面反光过强，塑料质感，高空向下看全是程序反光。

**根因**：fresnel 系数 0.98（几乎全反射天空）+ 太阳高光强度 0.9（强镜面）。

**修复**（[ocean.js](file:///c:/Users/CC/Desktop/gameSpace727/darkWil/js/ocean.js)）：
- fresnel 系数 0.98→0.45
- 太阳高光 0.9→0.3
- 高光指数 120（更柔和）
- 细碎法线按距离衰减（600-3000 区间，高空/远处消失）

### 1.3 海面小于底图露出深蓝背景（2026-08-04）

**现象**：海面跟随相机移动，飞远后海面边缘露出深蓝色背景。

**根因**：ocean size=30000 过小，跟随相机时边缘可见。

**修复**：
- ocean size 30000→60000
- 边缘 alpha 渐隐：`edgeFade = 1.0 - smoothstep(uOceanHalf - 5000.0, uOceanHalf, edgeDist)`，最后 5000m 从 1→0

### 1.4 海天交接深蓝色条带（2026-08-04）

**现象**：关闭场景雾后，海天交接处出现深蓝色硬边条带。

**根因**：场景雾关时海洋硬边没有雾融入，与天空色不衔接。

**修复**：海洋独立距离雾 `uFogDensity=0.0003`（不受场景雾影响），海平线远处融入天空色。场景雾 density=0 保证陆地清晰，海洋仍融入天空。

### 1.5 陆地后面是海洋（2026-08-04）

**现象**：飞过陆地后看到海洋（陆地后面应该一直是陆地）。

**根因**：地形 size 不够 + ocean 在陆地区域也渲染。

**修复**：
- 地形 size 增大到 48000（陆地纵深 19km）
- ocean shader 丢弃陆地区域：`if (vWorldPos.z < coastX - 30.0) discard;`

### 1.6 飞远回看陆地全白（2026-08-04）

**现象**：飞远后回看陆地，陆地全变白。

**根因**：场景雾气导致远处陆地被雾覆盖。

**修复**：关闭场景雾（density=0），海洋用独立雾。代价是陆地远处无雾融入，但陆地清晰。

### 1.7 天边云带串关（2026-08-05）

**现象**：barbarossa 关卡也出现天边云带（应仅在不列颠或显式开启时才有）。

**根因**：[environment.js](file:///c:/Users/CC/Desktop/gameSpace727/darkWil/js/environment.js) 默认 `cloudEnabled = skyClouds.enabled !== false`（默认开启），barbarossa 无 skyClouds 配置时走默认开。

**修复**：改为 `cloudEnabled = skyClouds.enabled === true`（默认关闭，需显式 `enabled: true` 才开启）。两关均无天边云带。

## 二、模型调试

### 2.1 喷火模型朝向反（yaw=180°）（2026-08-04）

**现象**：喷火模型机头朝反方向（180°）。

**根因**：`computeAutoOrient` 用 `getWorldPosition` 取节点 transform 原点。喷火 `Object_4` 的 transform 原点在机尾 Z=7.28，但几何中心在机头 Z=-6.61，导致算出的机头方向反向。

**修复**：改用 `Box3.setFromObject(o).getCenter()` 取几何中心，与游戏代码同步。同步修改 [tune_enemy.js](file:///c:/Users/CC/Desktop/gameSpace727/darkWil/js/tune_enemy.js) 的 `computeAutoOrient` + 暴露 `window.THREE`。

**验证**：`test_spit_prop.py`（旋转 90° 角点变化）。

**教训**：transform 原点 ≠ 几何中心，几何偏移节点（如 Blender 导出的 Object_X）必须用 Box3 取几何中心。

---

### 2.2 喷火起落架未隐藏（2026-08-04）

**现象**：配置了 `hideGearNodes` 但起落架仍可见。

**根因**：`MODEL_CONFIGS` 中未设置 `hideGear: true`，导致 `_hideLandingGear` 未调用。

**修复**：在 [enemy.js](file:///c:/Users/CC/Desktop/gameSpace727/darkWil/js/enemy.js) 喷火配置中添加 `hideGear: true`。

**教训**：`hideGearNodes` 是显式节点列表，但需要 `hideGear: true` 开关触发 `_hideLandingGear` 调用。

### 2.3 螺旋桨转速频闪（2026-08-04）

**现象**：敌机螺旋桨看起来转得慢，有频闪/视觉静止效果。

**根因**：`PROP_SPIN=120` rad/s，每帧旋转 114.6°，接近 3 桨叶 120° 间距，产生 wagon-wheel 效应（视觉静止）。

**修复**（[aircraft.js](file:///c:/Users/CC/Desktop/gameSpace727/darkWil/js/aircraft.js)）：
- `PROP_SPIN` 60→120→300 rad/s（每帧 286.5°，表观旋转 46.5°/帧向前）
- 桨叶 `opacity` 0.6→0.4→0.22（低透明度让高速旋转视觉暂留叠加成模糊盘）
- 频闪规避：避开 125.66 rad/s（120°/帧临界倒转点）

**教训**：3 桨叶频闪点 = 120° 间距 × 帧率对应的 rad/s，必须避开；配合低透明度呈现高速模糊盘。

### 2.4 通用模型预处理工具创建（2026-08-07）

**背景**：项目历史上有 4 个独立调试页面（`tune.html` 管炮口、`tune_enemy.html` 管敌机朝向、`tune_prop.html` 管螺旋桨、`tune_yak_models.html` 管 Yak 节点），功能分散、参数不互通，每次导入新模型要在多个页面间切换。

**方案**：整合为单一工具 `model_tuner.html`（2024 行），4 个 Tab 分区覆盖模型导入全流程：
- ① 基础坐标：autoOrient + Yaw/Pitch/Roll + userScale（按真实翼展自动算 3.6×翼展/9.92）+ centerOffset
- ② 机枪炮口：战斗机/轰炸机双模式，枪口标记球 + 弹道射线，支持增删炮口
- ③ 起落架：节点列表（按 Y/按名排序 + 过滤），勾选标记 + 实时隐藏预览
- ④ 螺旋桨：propNodes 标记 + 转速/透明度/模糊盘/轴倾斜/桨毂偏移

**关键设计**：
- `applyModelConfig` 严格复刻 `aircraft.js` 的 `_autoOrient`（按螺旋桨质心 Box3 几何中心算偏航）+ `_normalize`（最长维归一化到 9）+ `_setupPropPivot`（桨叶分组旋转），保证工具所见即游戏渲染
- 导出格式直接粘贴到 `js/enemy.js` 的 `MODEL_CONFIGS`，无需手工转换
- 参考机叠加：可加载另一机型作半透明叠加，对比调整
- 顶栏"应用并刷新"按钮模拟游戏内重新加载模型应用所有参数

**验证**：Spitfire 加载正常（66 节点、8 枪口、userScale 4.08），导出配置与 `enemy.js` 完全一致（autoOrient/yawOffset/hideGearNodes/propNodes/propSpinSpeed 全匹配）。

**教训**：
- 工具与游戏代码必须共享同一套校准算法（_autoOrient 的 Box3 取几何中心 vs transform 原点的差异曾导致喷火朝向反，见 2.1）
- 模块级临时变量重新赋值后，window 暴露的旧引用会失效（`__tuner.muzzles` 在 `muzzles = preset.map(...)` 后变空），验证时需读 DOM UI 而非暴露引用

### 2.5 玩家 Bf 109 移出工具范围（2026-08-07）

**现象**：玩家 Bf 109 在 `model_tuner.html` 中展示与游戏内渲染差异较大（朝向、座舱上抬、弹道方向都不同）。

**根因**：玩家 Bf 109 参数在 `aircraft.js` 构造函数硬编码，含特殊性：
- `aimLift=0.12`（座舱视角准星上抬，敌机恒为 0）
- `muzzleDirs=null`（共用 getAimDirection，敌机纯机头方向）
- autoOrient 逻辑路径不同

工具按敌机/友军通用逻辑处理玩家机型，导致渲染不一致。

**处理**：彻底移除 Bf 109 相关内容，工具只服务敌机/友军：
- 移除 MODEL_LIST/MODEL_CONFIGS/MUZZLE_PRESETS 中 bf109 条目
- 移除 aimLift/aimDist 控件 + player-badge 徽章 + syncPlayerBadge 函数
- 简化 effectiveMuzzleDir（移除 aimLift 分支，敌机弹道=纯机头方向）
- exportMuzzle/exportAll 移除 isPlayer 判断
- 启动默认加载首个敌机模型（Spitfire）

**教训**：工具应聚焦单一渲染路径（敌机/友军），混入玩家特殊性（座舱上抬、动态 aimLift）会导致校准逻辑分叉。玩家飞机将来单独做工具，处理 aimLift + aircraft.js 构造函数参数。

### 3.1 敌机出生位置不符合玩法（2026-08-05）

**现象**：敌机默认在玩家前方 1400-1900 出生，不符合不列颠"内陆出生→飞到海边盘旋→接敌"设计。

- WaveDirector._createEnemy 检测 wave.spawn/loiter 调 setSpawnBehavior；_spawnWave solo 分支检测 _spawnBehavior 时不覆盖 combatState

**隔离性**：barbarossa 关 wave 无 spawn/loiter → `_spawnBehavior=null` → 走原逻辑，完全不受影响。

### 3.2 _center 污染 bug（2026-08-05）

**现象**：`_thinkLoiter` 复用模块级 `_center`，会被其他敌机的 `_thinkSolo` 读取，导致 solo 敌机飞向 loiter 点。

**根因**：`_center` 是共享模块级 `THREE.Vector3`，`_thinkLoiter` 里 `_center.set(lb.x, lb.alt, lb.z)` 改变了值，下一帧 `_thinkSolo` 用 `target = _center` 时读到 loiter 点。

**修复**：加独立模块级 `_loiterTarget = new THREE.Vector3()`，`_thinkLoiter` 用 `_loiterTarget.set(...)` 不污染 `_center`。

**教训**：模块级临时向量是共享资源，若某方法 `set` 改变了它的值，其他方法读取时会读到污染值。要么用独立变量，要么确保同一帧不冲突。

## 调试方法论总结

1. **静态分析优先**：先读代码定位逻辑，再用 Playwright/截图验证
2. **隔离变量法**：bug 修复后检查是否有共享变量被污染（如 `_center` bug）
3. **从顶点到片元**：网格分辨率限制的着色问题，升级到片元级判定可彻底解决
4. **各向异性处理**：基于坐标轴的过渡在斜向边界会失效，需用等高线法线方向归一化
5. **频闪规避**：旋转动画的角速度必须避开视觉倒转点（`桨叶数 × 帧率 × 2π` 的倍数）
6. **注释与代码一致性**：注释说"已移至 X"时必须验证 X 真的被执行（如 onBeforeCompile 注入）
7. **隔离机制**：本关专用行为通过实例属性 + 配置注入，无配置走原逻辑，确保不串关
