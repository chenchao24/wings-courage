## 三、部署机制说明

- **⚠️ 关键坑：`wrangler pages deploy` 不读 `.assetsignore`**（它是 Workers 静态资产特性，Pages 上传路径不解析，2026-10-12 实测踩中）。因此**禁止直接 `wrangler pages deploy .`**，一律用 `scripts/deploy_pages.sh`：把发布集拷进 `_release/`（已 gitignore）再部署 `_release/`。脚本同时排除 3 个模型管线备份 glb。
- **不要把凭据写进任何会被部署/提交的文件**：git remote URL 用干净形式（无 token），push 时用一次性带 token 的 URL 或系统凭据管理器。`.git/` 一旦被打包部署，`.git/config` 里的凭据会公开。
- **`_headers`**（发布集根目录）：Pages 缓存策略——`/model` `/sound` `/img` `/vendor` 缓存 1 周，`/js` 1 小时，HTML 不缓存。
  - ⚠️ 资产文件名无 hash：**替换同名模型/音频/图片后，边缘节点旧缓存最长 1 周才过期**。需要立即生效时，给文件改名（如 `b17-v2.glb`）并同步改代码引用。
  - ⚠️ **删除文件同理**：已上线过的文件被移除后，边缘缓存可能继续提供旧内容直到 TTL 过期（属正常，新访客/新节点不受影响）。
- **必须根路径部署**：全站资源用 `/js/`、`/model/` 等绝对路径，不支持子路径部署。
- 单文件 25MiB 上限（Pages 限制）：当前最大文件约 3MB，余量充足。
- Pages 对未命中路径回退到 `index.html`（SPA 行为），所以验证"文件是否已排除"要看返回内容是否为首页（3648B），不能只看 200 状态码。

## 六、故障排查

| 症状 | 处理 |
|---|---|
| `git push` 连不上 github.com | 网络对 GitHub 直连不稳，多重试几次；或配置代理 `git config http.proxy http://127.0.0.1:端口`（本机代理软件端口） |
| wrangler 报 401/403 | Token 过期或权限不足，重新生成（需 Pages 编辑权限） |
| wrangler 上传中途失败 | 直接重跑同一命令，wrangler 会跳过已上传文件 |
| curl 调 CF API 报 CRYPT_E_REVOCATION_OFFLINE | Windows curl 加 `--ssl-no-revoke` |
| 部署后页面白屏 | F12 看 Console；确认部署集完整（index.html/js/vendor/model/sound/img），确认没有 404 |
