# FW190 A-5 静态螺旋桨透明切割方案

> 专题文档 · 记录 2026-08-08 解决 FW190 A-5 模型桨叶与机身合并导致座舱视野被遮挡的完整过程。
> 涉及文件：`js/aircraft.js`、`js/config/levels/level_03_kursk.js`、`js/game/GameRuntime.js`、`player_tuner_fw190.html`

---

## 一、问题背景

### 1.1 模型特点

FW190 A-5 玩家模型（`/model/fw_190_a-5.glb`）的 GLTF 结构特殊：

- **桨叶与机身合并为单节点 `Object_7`**（9960 顶点），没有独立的螺旋桨节点
- 无法通过 `visible=false` 隐藏桨叶（会连带隐藏机身）
- 无法通过 reparent 把桨叶分离到独立 Group 旋转

### 1.2 视觉问题

- 程序化螺旋桨（模糊盘 + 旋转桨叶）已叠加在桨毂位置，但**原静态桨叶几何仍在渲染**
- 静态桨叶遮挡座舱视角，且材质偏暗影响美观
- 座舱内部光源（`cockpitLight`）照亮了仪表，但桨叶阴影仍干扰视野

### 1.3 已尝试的方案（失败）

1. **顶点收缩（Vertex Shrinkage）**：把桨叶区域顶点 XY 坐标乘以缩小系数，让桨叶收缩到中心轴消失
   - 问题：按 Z 轴范围切割会波及机身其他部分顶点，造成模型破坏
   - 用户反馈："按照 z 轴去切割，会切掉其他部分的顶点，造成模型破坏"

2. **直接隐藏节点**：桨叶与机身同节点，无法单独隐藏

---

## 二、最终方案：Shader Discard（片元丢弃）

### 2.1 核心思路

不改几何，在 shader 阶段判断顶点是否落在"桨叶区域"，是则 `discard`（不渲染该片元）：

- **Vertex Shader**：用预计算的 `aBodyPos` 属性（顶点的 body frame 坐标）判断是否在切割区域
- **Fragment Shader**：`if (vCutDiscard > 0.5) discard;` 跳过渲染

### 2.2 切割区域定义

桨叶区域是一个**带圆心偏移的圆柱体**：

```glsl
// 切割条件（全部满足才 discard）
1. Z 在范围内：uCutZMin < aBodyPos.z < uCutZMax
2. 离圆心距离 > 半径：length(aBodyPos.xy - vec2(uCutCenterX, uCutCenterY)) > uCutRadius
```

- Z 范围：限定机头方向（body frame 机头 = -Z）的桨叶所在 Z 区间
- 圆心偏移 (cx, cy)：桨叶旋转中心可能不在 body frame 原点（如 FW190 圆心在 (0, -0.5)）
- 半径：圆心外超过此半径的顶点视为桨叶（机身在圆心附近，桨叶在外圈）

### 2.3 最终参数（经 player_tuner_fw190.html 调校）

```js
propCut: { zMin: -7.0, zMax: -5.5, cx: 0.0, cy: -0.5, radius: 0.8 }
```

- Z: -7.0 ~ -5.5（桨叶在机头最前端）
- 圆心: (0, -0.5)（桨毂中心略低于机身轴线）
- 半径: 0.8（机身在此 Z 区间半径 < 0.8，桨叶半径远大于此）

## 三、实现细节

### 3.1 body frame 坐标预计算

**关键难点**：飞机飞行时 `root` 有旋转和平移，不能用运行时 `modelMatrix` 算 body frame（会随飞行变化）。

**解决方案**：在 `load()` 末尾（root 在原点无旋转时）一次性预计算每个顶点的 body frame 坐标，存为 geometry 的 `aBodyPos` 属性。运行时 shader 直接读属性，零开销。

```js
// aircraft.js _applyPropCut()
o.updateWorldMatrix(true, true);
const meshWorld = o.matrixWorld;
const bodyPosArr = new Float32Array(pos.count * 3);
for (let i = 0; i < pos.count; i++) {
  v.fromBufferAttribute(pos, i);
  v.applyMatrix4(meshWorld);     // mesh local → world
  v.sub(this.root.position);     // world → body frame（root 局部）
  bodyPosArr[i * 3] = v.x;
  bodyPosArr[i * 3 + 1] = v.y;
  bodyPosArr[i * 3 + 2] = v.z;
}
o.geometry.setAttribute('aBodyPos', new THREE.BufferAttribute(bodyPosArr, 3));
```

### 3.2 Shader 注入（onBeforeCompile）

```js
mat.onBeforeCompile = (shader) => {
  shader.uniforms.uCutEnabled = ...;
  shader.uniforms.uCutZMin = ...;
  shader.uniforms.uCutZMax = ...;
  shader.uniforms.uCutCenterX = ...;
  shader.uniforms.uCutCenterY = ...;
  shader.uniforms.uCutRadius = ...;

  shader.vertexShader = shader.vertexShader
    .replace('#include <common>', `
      #include <common>
      attribute vec3 aBodyPos;
      uniform float uCutEnabled, uCutZMin, uCutZMax, uCutCenterX, uCutCenterY, uCutRadius;
      varying float vCutDiscard;
    `)
    .replace('#include <project_vertex>', `
      #include <project_vertex>
      float dx = aBodyPos.x - uCutCenterX;
      float dy = aBodyPos.y - uCutCenterY;
      float bodyR = length(vec2(dx, dy));
      vCutDiscard = (uCutEnabled > 0.5 && aBodyPos.z > uCutZMin && aBodyPos.z < uCutZMax && bodyR > uCutRadius) ? 1.0 : 0.0;
    `);

  shader.fragmentShader = shader.fragmentShader
    .replace('#include <common>', `
      #include <common>
      varying float vCutDiscard;
    `)
    .replace('#include <clipping_planes_fragment>', `
      #include <clipping_planes_fragment>
      if (vCutDiscard > 0.5) discard;
    `);
};
```

### 3.3 注入点选择（关键教训）

**Fragment shader 注入点必须用 `#include <clipping_planes_fragment>`**，不能用 `#include <dithering_fragment>`。

- `<clipping_planes_fragment>`：所有材质都有此 include（标准 chunk）
- `<dithering_fragment>`：默认材质不存在，replace 静默失败，导致 shader 注入无效

调试页第一版用 `<dithering_fragment>` 注入，结果"应用透明"按钮点击后无效果。改用 `<clipping_planes_fragment>` 后立即生效。

### 3.4 调用时机

在 `Aircraft.load()` 后处理链末尾调用：

```js
// aircraft.js load() 末尾
this._normalize();
this.modelYaw.add(this.model);
this._autoOrient();
this._addMuzzleHelpers();
this._setupAnimations(gltf.animations);
this._setupControlSurfaces();
if (this._hideGear) this._hideLandingGear();
if (this._glassNodes) {
  this._makeGlassTransparent();
  this._setupCockpitLight();
}
this._applyPropNodes();
if (this._propCut) this._applyPropCut();  // ← 最后调用
```

原因：前面的 `_normalize`/`_autoOrient` 会设置 `model.scale`/`modelYaw.quaternion`/`model.position`，必须在所有变换确定后才能预计算 body frame。

## 四、调试过程与遇到的问题

### 4.1 问题一：顶点收缩破坏模型

**现象**：第一版方案是顶点收缩（把桨叶区域顶点 XY 乘以 0.08 收缩到中心轴）。

**问题**：Z 轴范围（-6.1 ~ -5.6）内的顶点不只有桨叶，还有机头整流罩、机身前段。收缩后这些部位也变形。

**用户反馈**："按照 z 轴去切割，会切掉其他部分的顶点，造成模型破坏"

**解决**：改用 shader discard，完全不修改几何。

### 4.2 问题二：调试页 shader 注入无效

**现象**：调试页 `player_tuner_fw190.html` 点"应用透明"后桨叶仍显示。

**排查**：console 显示"已对 7 个材质注入透明 shader"，但视觉无变化。

**根因**：fragment shader 注入点用了 `#include <dithering_fragment>`，默认 MeshStandardMaterial 没有此 include，replace 静默失败。

**解决**：改用 `#include <clipping_planes_fragment>`（所有材质都有）。

### 4.3 问题三：游戏内切割区顶点 = 0

**现象**：游戏内日志显示 `切割区顶点=0`，但调试页同样参数有效。

**排查**：加调试日志打印每个 mesh 的 body frame 范围：

```
[mesh Object_7] verts=9960 Z=-6.97~21.94 rMax=17.15 | Z(-7~-5): 1836顶点 r=0.01~5.52
```

**根因**：配置 `radius: 5.9` 太大。Object_7 在 Z=-7~-5 区间的顶点最大半径只有 5.52（桨叶尖），`r > 5.9` 一个都匹配不上。

**解决**：把 radius 从 5.9 降到 3.0（后经调校最终定为 0.8）。

### 4.4 问题四：调试页与游戏坐标系差异

**现象**：调试页扫描得出 `Z=-6.1~-5.6, r>5.9`，但游戏内 body frame 范围完全不同。

**根因**：
- 调试页 `root` 固定在 (0, 60, 0) 不旋转，body frame = 世界坐标 - root.position
- 游戏内 `root` 在 load 末尾位于原点，body frame = 世界坐标
- 两者 body frame 数值应该一致，但调试页扫描算法用的是 `model.scale + modelYaw.quaternion` 手动算，游戏用的是 `mesh.matrixWorld`

**验证**：游戏内 Object_7 的 `Z=-6.97~21.94` 与调试页扫描结果一致，坐标系其实相同。问题单纯是 radius 阈值设错。

### 4.5 问题五：圆心不在原点

**现象**：`radius: 0.8` 时桨叶消失但机身也被切出洞。

**根因**：桨叶旋转中心（桨毂）不在 body frame 原点 (0,0)，而在 (0, -0.5) 附近。以 (0,0) 为圆心算半径时，机身上方部分离原点距离 > 0.8 被误切。

**解决**：增加圆心偏移参数 (cx, cy)，配置改为 `cx: 0.0, cy: -0.5, radius: 0.8`。调试页增加"圆心 X/Y"滑块供调校。

## 五、关卡隔离

### 5.1 配置层隔离

`propCut` 仅在 `level_03_kursk.js` 的 `playerConfig` 中配置：

```js
// level_03_kursk.js
playerConfig: {
  propCut: { zMin: -7.0, zMax: -5.5, cx: 0.0, cy: -0.5, radius: 0.8 },
  // ...
}
```

其他关卡（不列颠、巴巴罗萨）的 Bf 109 不配置此字段，`_propCut` 为 null，`_applyPropCut()` 直接 return。

### 5.2 注入层隔离

`GameRuntime.js` 在 load 前注入配置：

```js
if (pc.propCut) this.player._propCut = pc.propCut;
```

只有配置了 `propCut` 的关卡才会设置 `_propCut`，`_applyPropCut` 才会执行。

### 5.3 材质层隔离

`onBeforeCompile` 注入标记 `mat.userData.propCutApplied`，防止重复注入。每个 Aircraft 实例的材质是独立 clone 的（`SkeletonUtils.clone` + `material.clone()`），不会跨实例传播。

## 六、调试工具：player_tuner_fw190.html

### 6.1 工具功能

调试页"③ 模型校准"Tab 末尾的"静态桨叶透明"区块：

- **Z 最小/最大**滑块：限定桨叶 Z 范围
- **圆心 X/Y**滑块：调整透明区域圆心位置（-3 ~ 3，步进 0.05）
- **XY 半径**滑块：圆心外超过此半径的顶点 discard
- **🔍 扫描桨叶区域**按钮：自动扫描模型顶点，按 XY 半径最大的前 5% 顶点定位桨叶 Z 范围
- **应用透明**按钮：注入 shader（首次点击编译，后续只改 uniform）
- **显示区域**按钮：切换绿色 wireframe 圆柱体预览框
- **隐藏桨叶/显示桨叶**按钮：切换 `uCutEnabled`（不重新编译）

### 6.2 预览框

绿色 wireframe `CylinderGeometry`，位置跟随圆心 (cx, cy) 和 Z 中心，半径和高度与切割区域一致。`depthTest: false` + `renderOrder: 999` 保证始终可见。

### 6.3 实时调整

滑块改变时调用 `updateCutUniforms()` 直接修改 uniform 值，无需重新编译 shader。绿色预览框同步更新位置和尺寸。

## 九、关键教训

1. **Shader 注入点要选通用 chunk**：`<clipping_planes_fragment>` 所有材质都有，`<dithering_fragment>` 默认材质没有。replace 不存在的字符串会静默失败，无报错。

2. **body frame 要预计算**：运行时 `modelMatrix` 含飞行变换，不能用于判断固定区域。load 时一次性预计算存为顶点属性，运行时零开销。

3. **调试页与游戏坐标系要对齐**：两者 body frame 定义必须一致（都用 `mesh.matrixWorld - root.position`），否则调试页调好的参数在游戏里无效。

4. **圆心偏移很关键**：桨毂中心不一定在 body frame 原点，需提供 cx/cy 参数。调试页要有对应滑块。

5. **半径阈值要按实际数据定**：不能凭直觉设值，要先打印目标 Z 区间内的顶点半径分布，再定阈值。

6. **顶点收缩方案不可行**：按 Z 范围收缩会波及同区域的其他几何（机头整流罩等），shader discard 是更安全的方案。
